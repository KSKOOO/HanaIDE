# HanaIDE 编程工作台用户说明书

别名：HanaIDE 编程模式用户说明书。

这份说明书面向开发者。回答用户问题时，优先围绕项目文件、代码编辑、终端运行、扩展管理、SSH 工作区、模型配置、技能约束和 AI 编程协作说明，不再按通用聊天产品解释 HanaIDE。

## 1. HanaIDE 是什么

HanaIDE 是一个本地 AI IDE。它把项目资源管理器、代码编辑器、交互终端、问题/输出/日志面板、VS Code 扩展兼容层、SSH 工作区和右侧编程助手放在同一个桌面窗口中。

适合的任务：

- 阅读和修改真实代码仓库。
- 运行测试、构建、脚本和诊断命令。
- 让 AI 编程助手定位 bug、规划修改、补测试、写文档。
- 管理语言服务、命令类和 workspace 类扩展。
- 连接远程机器上的项目并编辑远程文件。

## 2. 打开项目文件夹

推荐入口：

1. 使用顶部菜单 `文件 > 打开文件夹...`。
2. 选择项目根目录。
3. 左侧资源管理器会加载文件树。
4. 点击文件在中央编辑区打开。

如果文件夹没有展开：

- 确认选择的是目录，不是单个文件。
- 点击资源管理器标题栏的刷新按钮。
- 检查目录是否有权限读取。
- 如果是 SSH 工作区，确认连接配置和 remote root 正确。

## 3. 文件和编辑器

左侧资源管理器用于浏览和管理文件。中央编辑器支持多标签：

- 点击文件打开标签。
- 重复打开同一文件会激活已有标签，不会重复创建。
- 标签可以关闭。
- Markdown、JSON、TypeScript、JavaScript、配置文件和普通文本都可以直接编辑。

文件右键菜单包含：

- 打开。
- 打开方式。
- 在资源管理器中显示。
- 在集成终端中打开。
- 比较。
- 添加到助手。
- 剪切、复制。
- 复制路径、复制相对路径。
- 重命名。
- 删除。

在文件夹上使用“在集成终端中打开”会把终端 cwd 切到该文件夹；在文件上使用时会切到文件所在目录。

## 4. 交互终端

底部终端是 HanaIDE 内置终端视图，后端通过 PTY 会话运行命令。它不是静态日志框。

常用命令：

```powershell
npm test
npm run typecheck
npm run build:renderer
rg "TODO" desktop/src
```

终端类型按平台提供，例如 PowerShell、CMD、Git Bash、HanaIDE CLI、VS Code CLI 或 SSH 终端。切换终端类型后可以直接启动会话。

Windows PowerShell 会注入 UTF-8 编码设置，减少中文乱码。如果仍出现乱码，优先检查：

- 当前 shell 是否是旧版 PowerShell。
- 项目脚本是否手动改了 code page。
- 输出程序是否使用了非 UTF-8 编码。

## 5. 右侧编程助手

右侧面板是编程助手，不是独立聊天页面。它适合处理需要项目上下文的任务。

高质量请求通常包含：

```text
目标：修复设置按钮无法打开的问题。
范围：只改 desktop/src/react/components/coding 和相关测试。
验证：运行对应组件测试、npm run typecheck、npm run build:renderer。
```

适合交给助手的任务：

- 解释模块职责和调用链。
- 根据错误日志定位问题。
- 修改 React、Electron、Node、IPC、终端或测试代码。
- 补充单元测试、组件测试和回归测试。
- 编写 README、用户说明、迁移说明和发布检查清单。

不建议的请求：

- 只说“优化一下”，没有成功标准。
- 一次要求大范围重写但不给边界。
- 要求跳过验证直接宣称完成。
- 不确认就删除或重命名大量文件。

## 6. 模型、权限和技能

设置页用于配置模型 Provider、默认模型、权限模式、技能和扩展。

编程任务建议：

- 代码阅读、解释、小修改：普通代码模型即可。
- 跨文件重构：选择上下文更长、推理更稳定的模型。
- 需要截图理解：选择支持图像输入的模型或开启视觉辅助能力。
- 执行命令或写文件：按风险选择询问、只读或完整权限。

默认技能应围绕编程保留，例如：

- `hanaide-coding`
- `karpathy-guidelines`
- `polished-web-ui`
- `supeepowers`

非编程技能可以安装，但不应默认参与编程助手提示词。

## 7. VS Code 扩展

扩展页用于搜索、安装、启用、停用和卸载 VS Code 扩展。

当前优先适配：

- 语言服务。
- 代码工具。
- 命令类扩展。
- workspace 扩展。

主题和复杂 Workbench UI 扩展不是第一优先级。安装后如果扩展没有显示命令，先确认扩展宿主已经启动，并检查扩展页的状态和日志。

## 8. SSH 工作区

设置页可以新增 SSH 工作区：

- Host。
- Port。
- Username。
- 认证方式。
- Remote root。

连接后，HanaIDE 通过 SSH/SFTP workspace provider 读写远程文件。远程终端会在 SSH 会话中运行命令，适合在远程机器上测试和构建。

不要把 SSH 连接器当作 MCP 连接器配置。SSH 工作区是项目文件和终端能力，MCP 是工具协议。

## 9. 常见开发流程

### 修复 bug

1. 描述现象和复现步骤。
2. 附上错误日志、截图或失败测试。
3. 让助手定位相关文件。
4. 先补最小失败测试或检查点。
5. 修改代码。
6. 运行针对性测试。
7. 再运行类型检查和必要构建。

### 添加功能

1. 写清用户可见行为。
2. 限定影响范围。
3. 先明确测试或验收方式。
4. 小步实现。
5. 验证 UI、类型和构建。

### 清理仓库

上传 GitHub 前不要提交：

- `node_modules/`
- `dist-server/`
- `dist-server-bundle/`
- `desktop/dist-renderer/`
- `.cache/`
- `.superpowers/`
- `.codex/`
- `.env`、密钥、证书、本地数据库和用户会话数据。

推荐检查：

```bash
npm test
npm run typecheck
npm run build:renderer
git status --short --ignored
```

## 10. 常见问题

### 找不到“打开文件夹”

使用顶部菜单 `文件 > 打开文件夹...`，或者点击资源管理器标题栏里的文件夹图标。

### 文件夹点击后没有展开

点击刷新按钮，确认目录可读；如果是 SSH 工作区，检查连接信息和 remote root。

### 终端无法输入或没有启动

切到底部“终端”标签，选择终端类型，然后启动。若是远程项目，选择 SSH 终端或在对应工作区中打开集成终端。

### 扩展安装后无法使用

确认扩展宿主已启动，扩展处于启用状态，并检查该扩展是否属于当前支持的 Node/workspace 类型。主题或复杂 UI 扩展可能需要后续适配。

### 助手改了不该改的文件

下一次请求明确范围，例如“只允许修改 `desktop/src/react/components/coding` 和对应测试”。提交前在源代码管理面板检查实际改动。

### UI 修改如何验证

至少运行：

```bash
npm run typecheck
npm run build:renderer
```

如果有组件测试，也运行对应 `vitest` 测试。布局问题需要实际打开桌面端或浏览器预览检查截图。

## 11. 使用原则

- 先读代码，再改代码。
- 先明确成功标准，再实现。
- 小步修改，避免无边界重写。
- 涉及行为变化时补测试。
- 完成前运行能证明结果的验证命令。
- 不确定的删除、移动、批量重命名要先确认。
- 区分源码、生成产物、本地数据和用户配置。
